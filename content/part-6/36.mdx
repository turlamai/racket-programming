# 延续——Racket 里的时间旅行

> 延续（continuation）是“计算剩下要做的事”。`call/cc` 把它打包成一个可调用的值，你可以存起来、传出去、以后再跳回去。恢复捕获的延续需要遵守提示边界和运行时约束。

前面我们已经学会调用函数：函数算出结果后，调用它的表达式便可以继续计算。但你有没有想过：要是能保存住“此刻之后程序要做的全部事”，以后随时跳回这个点，甚至跳好几次呢？

Racket 把“计算的剩余部分”做成了一等公民，可以存进变量、传来传去、随时调用。这就是延续。它与普通返回的区别是可以在允许的控制边界内恢复此前捕获的计算。

## 延续，就是“接下来要做的事”

一行代码正在运行时，它之后还要做的事，就是它此刻的延续。

```racket
(+ 1 (* 2 3))
```

求值 `(* 2 3)` 那一刻，它的延续是“把结果乘出来之后，加 1”。平时这个“剩余部分”是隐式的——求值器替你记着，做完一步自动做下一步。Racket 的 `call/cc` 把它显式地交到你手里。

## call/cc：把剩余计算变成一个值

`call/cc` 是 `call-with-current-continuation` 的简写。它接收一个函数，并把当前延续交给这个函数。延续的捕获范围由最近的匹配提示（prompt）限定。提示像一个控制流的边界：我们可以明确指定希望捕获哪一段计算。

下面的例子使用独立的提示标签，避免把模块初始化或后续测试也意外纳入延续。

```racket
#lang racket

(define tag (make-continuation-prompt-tag 'demo))
(define saved-k #f)

(define (within thunk)
  (call-with-continuation-prompt thunk tag))

(within
 (lambda ()
   (+ 1
      (call/cc
       (lambda (k)
         (set! saved-k k)
         10)
       tag))))
;; 11

(within (lambda () (saved-k 100)))
;; 101

(within (lambda () (saved-k 200)))
;; 201
```

第一次执行时，`call/cc` 接收的函数正常返回 10，因此外层加法得到 11。同时，saved-k 保存了提示边界内等待一个值、再加 1 的控制上下文。

第二次执行时，我们在新的同标签提示内调用 saved-k，传入 100。当前提示内的控制上下文被替换为保存的上下文，于是得到 101。第三次传入 200，得到 201。

## 延续不是状态快照

可以把调用延续想象成恢复一段尚待执行的计算，但它不是把整个程序倒回过去。捕获点之前的代码不会因此重跑，已经修改的变量、写入的文件也不会自动恢复。

普通过程返回到调用处，而延续可以在规定的提示边界和其他运行时约束下转移控制流。这样的机制能够表达非本地退出、生成器与其他控制结构。

## 用得最多的形态：非本地退出

`call/cc` 的全部威力，在大多数场景里用不上。八成的情况，你只是想从深层嵌套里提前跳出来。这时该用的是 escape continuation——作用范围更明确：

```racket
#lang racket

(define (find-first pred lst)
 (let/ec exit ; let/ec 是 call/ec 的简写
 (for ([x (in-list lst)])
 (when (pred x)
 (exit x)))
 #f))

(find-first even? '(1 3 5 8 9))
;; 8
```

`let/ec`（背后是 `call/ec`，全名 `call-with-escape-continuation`）捕获的延续只能在其动态作用范围内调用；调用会退出该范围。

**escape continuation 适合表达有明确动态范围的提前退出。** 需要提前退出、跳出循环、中断递归，都用它；把全功能的 `call/cc` 留给真正要“跳回去好几次”的场景。

## 延续与生成器

生成器可以通过受提示边界限制的延续实现。与其捕获整个调用者的控制上下文，不如使用独立提示标签，只保存生成器内部尚待执行的部分。下面先使用标准库提供的接口观察暂停与恢复：

```racket
#lang racket
(require racket/generator rackunit)

(define g
  (generator ()
    (yield 'a)
    (yield 'b)
    'finished))

(check-equal? (g) 'a)
(check-equal? (g) 'b)
(check-equal? (g) 'finished)
(check-equal? (generator-state g) 'done)
```

保存为 continuation-generator.rkt，运行 raco test continuation-generator.rkt。预期四项检查通过。下一章进一步讨论 yield 与可组合延续的关系。实际项目优先使用经过维护的标准库接口，而不是自行保存未经限定的调用者延续。

## Web 会话中的延续

Racket web-server 的 send/suspend 可以暂停 servlet 的计算，并生成与该延续关联的 URL。浏览器随后请求该 URL 时，服务器可以将新的请求交给暂停的计算。

这个机制可以表达多步骤表单，但不意味着会话具有无限生命周期，也不能替代身份认证、权限验证、CSRF 防护和持久化。服务器重启、延续过期或重复提交都需要单独考虑。有关具体接口，参阅 [Web Server 文档](https://docs.racket-lang.org/web-server/)，本书第七卷还将使用普通路由与显式状态实现 Web 应用。

## dynamic-wind：跳走之前，打扫干净

延续能任意跳转，引出一个问题：如果一个 `call/cc` 跳出了“已经打开文件、拿到锁”的代码块，那些清理代码还跑吗？默认是不跑——你跳走就跳走了。`dynamic-wind` 就是来解决这个的：

```racket
#lang racket
(require rackunit)

(define tag (make-continuation-prompt-tag 'wind-demo))
(define saved-k #f)
(define trace '())
(define (record! item)
  (set! trace (cons item trace)))
(define (within thunk)
  (call-with-continuation-prompt thunk tag))

(within
 (lambda ()
   (dynamic-wind
    (lambda () (record! 'enter))
    (lambda ()
      (record! 'before)
      (call/cc (lambda (k) (set! saved-k k) 'first) tag)
      (record! 'after))
    (lambda () (record! 'leave)))))

(check-equal? (reverse trace)
              '(enter before after leave))
(set! trace '())
(within (lambda () (saved-k 'again)))
(check-equal? (reverse trace)
              '(enter after leave))
```

首次进入动态范围时依次记录 enter、before、after、leave。再次恢复延续时，进入动作重新运行，但捕获点之前的 before 不会重跑；恢复后的 after 与退出动作会执行。保存为 wind-demo.rkt，执行 raco test wind-demo.rkt，预期两项检查通过。

进入和退出函数需要按照可能多次进入、离开的语义设计。dynamic-wind 并不会自动恢复已经关闭的资源，也不是强制终止线程时的通用清理保证。

## 延续也有跨不过的边界

延续不是无所不能。Racket 会在一些控制上下文（例如宏转换器及异常处理器的调用）安装 continuation barrier。若应用延续需要进行不允许的跨边界控制转移，就会抛出 exn:fail:contract:continuation。匹配的 prompt 是否存在、延续的类型以及实际控制上下文共同决定操作是否合法。参阅 [Continuation Reference](https://docs.racket-lang.org/reference/cont.html)。

这是有意为之——它把“乱跳”限制在了一个可控的范围里。日常应用代码几乎不会撞上这道墙，但要知道它在那儿。

## 强力药，点到为止

延续是 Lisp 家族最强大的控制结构之一，能表达协程、生成器、异常、Web 会话——一切“非线性流程”。但它也是典型的“读起来费劲”特性：一个 `call/cc` 让执行流能飞到任何地方，调试时这是噩梦。

实用的态度是分层：先用 `let/ec` / `call/ec` 解决提前退出，用 `racket/generator` 解决迭代器，用 `send/suspend` 解决 Web 会话。这些都是在延续之上包好的安全壳。**真要自己手写 `call/cc` 时，把它封装成一句注释能讲清的小模式，别让它裸露在业务代码里。** 延续是把流程变成数据的力量，但好钢用在刀刃上。
