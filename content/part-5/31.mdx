# Glaze——任务列表、界面布局与应用状态

> 一个应用不只是一个按钮。本章用任务管理器学习怎样组织业务规则、界面状态、持久化和错误处理，并阅读真实的 Glaze Taskboard 示例。

第 30 章中，按钮把一个名字交给 Racket，再显示问候语。现在我们希望用户可以添加任务、勾选完成、删除任务，并在重新启动应用后找回数据。

## 先定义任务，而不是先画窗口

第 29 章已经介绍过 task 结构体。本章先用一个独立的 Racket 模块练习添加任务的规则。这个简化模型只负责标题和完成状态，不包含文件读写，也不依赖 Glaze。

保存为 task.rkt：

```racket
#lang racket/base
(require racket/string)
(provide (struct-out task) add-task finish)

(struct task (title note done?) #:transparent)

(define (add-task tasks title)
  (define clean (string-trim title))
  (if (<= 1 (string-length clean) 120)
      (append tasks (list (task clean "" #f)))
      #f))

(define (finish t)
  (struct-copy task t [done? #t]))

(module+ test
  (require rackunit)
  (define xs (add-task '() "  买牛奶  "))
  (check-equal? (task-title (car xs)) "买牛奶")
  (check-false (add-task xs " "))
  (check-false (task-done? (car xs)))
  (check-true (task-done? (finish (car xs)))))
```

运行 raco test task.rkt。这里返回新列表而不修改旧列表；无效标题返回 #f。真正的应用还需要稳定的任务标识、错误处理和存储约束。本章的小模块是学习业务规则的独立练习，不是官方 Taskboard 的替换文件。

## 认识真实项目

Glaze 仓库维护了 [Taskboard 示例](https://github.com/turlamai/glaze/tree/HEAD/examples/taskboard)。若已经从源码安装 Glaze，进入该目录：

```sh
raco glaze doctor --json
raco glaze schema check --json
raco glaze dev
```

关闭窗口后运行：

```sh
raco test tests/*.rkt
raco glaze verify
```

Windows PowerShell 可逐个传入 tests 目录中的 .rkt 文件。verify 检查原生窗口，业务流程还需要 API 测试和实际操作验收。

先读 taskboard.rkt，它定义 task-add、task-toggle、task-remove 和 task-stats。真实示例使用哈希表表达任务，包含 id、title、done、created 字段。再读 main.rkt，最后读 public 下的 HTML、JS 和 CSS。

## 从输入到状态

在真实示例的 main.rkt 中，创建任务的 API 声明如下（摘取原模块中的一个路由，依赖该模块已有的辅助函数）：

```racket
[(POST "api/tasks/create")
 (createTask [title GString ""])
 (or (mutate! (lambda (current)
                (task-add current title (current-seconds))))
     (invalid! "title must be 1-120 characters and not blank"))]
```

调用方使用生成的 glaze.api.createTask 方法。GString 检查数据类型，task-add 检查业务规则，两者不能互相替代。

![任务管理应用中界面输入、领域规则、存储与状态更新的边界](/images/taskboard-state-flow.svg)

状态更新由后端集中处理。当前示例用信号量保护读、修改、写入的过程；通过 store 保存任务，并广播新的状态快照。自动保存带有延迟，因此不能把每次成功响应等同于数据已立即写入持久介质。

## 布局与交互

一个最小任务管理界面可以由标题、添加表单、任务列表和统计信息组成。HTML 定义这些结构，CSS 决定排列和间距，JavaScript 把用户操作转换为 API 调用。

例如，以下 CSS 是一个可放入独立页面的布局练习：

```css
.board {
  max-width: 640px;
  margin: 24px auto;
  padding: 16px;
}
.task-row {
  display: flex;
  align-items: center;
  gap: 12px;
}
.task-title {
  flex: 1;
  min-width: 0;
  overflow-wrap: anywhere;
}
```

flex 让一行的子元素共享可用空间，gap 指定间距。任务标题允许换行，不依赖固定像素宽度。使用真正的 button、input 和 label 元素，保留键盘操作与可访问名称。

## 两种状态不要混在一起

输入框里尚未提交的文字属于界面草稿；后端已经接受的任务属于业务状态。提交失败时保留草稿，展示错误，不应直接把失败的操作显示成已保存。

筛选条件（全部、未完成、已完成）通常是界面状态。用同一个任务列表计算不同展示结果即可，不必为了筛选而修改持久化数据。

## 验收与发布

在独立测试数据目录中检查：空标题被拒绝；有效任务可添加；勾选完成后统计改变；删除后列表正确；关闭再打开后数据恢复；失败时页面仍保留用户输入。官方示例可通过 TASKBOARD_DATA_DIR 指定隔离目录，具体使用方式见示例 README。

请不要拿真实用户数据作为破坏性测试对象。发布前还要验证目标平台的 WebView、打包、签名与安装流程。
