# Glaze——从零开发第一个桌面应用

> Glaze 将 Racket 业务逻辑与 HTML、CSS、JavaScript 界面连接起来，在操作系统提供的原生 WebView 窗口中运行。本章从一个按钮开始，走通界面与后端之间的调用。

上一章介绍了三种桌面界面路线。本章选择 Glaze，下一章进一步组织界面和数据。第 32 章再学习 Rivet 的平台原生控件路线。

## 先认识界面的三种语言

HTML 描述页面有哪些元素，例如标题和按钮；CSS 描述这些元素如何排列、使用什么颜色和尺寸；JavaScript 负责响应点击等交互。WebView 是操作系统提供的页面渲染组件，可以将这些页面嵌入桌面窗口。它不是要求用户另开浏览器。

Racket 在这个例子里负责生成问候语。界面将用户输入交给 Racket，Racket 返回结果，再由 JavaScript 更新页面。

## 安装与创建项目

使用 Racket 9.0 或更新版本的 CS 实现。在终端运行：

```sh
racket --version
raco pkg install --auto glaze
raco glaze help
raco glaze init myapp
cd myapp
raco glaze doctor --json
```

Windows 需要 WebView2 Runtime；macOS 使用 WKWebView，需要图形会话；Linux 需要 GTK 3、WebKitGTK 和图形会话。doctor 用于检查依赖，不等于已经验证窗口可用。具体平台要求以 [Glaze 官方入门指南](https://github.com/turlamai/glaze/blob/master/docs/getting-started.md) 为准；若链接随默认分支变动，可从 [项目仓库](https://github.com/turlamai/glaze) 进入 docs。

初次创建后先认识三个文件：

| 文件 | 用途 |
|---|---|
| main.rkt | Racket 业务逻辑、API 定义和启动入口 |
| public/index.html | 页面结构、样式与交互 |
| glaze-schema.json | 应用 API 的兼容性基线 |

## 第一步：编写 Racket 后端

将 main.rkt 替换为：

```racket
#lang racket/base
(require racket/runtime-path glaze)
(define-runtime-path public "public")

(define-api-routes api
  [(POST "api/greet")
   (greet [name GString "World"])
   (hasheq 'message (string-append "你好，" name "！"))])
(provide api)

(module+ main
  (run-app #:public-dir public
           #:api api
           #:title "我的第一个应用"))
```

这里定义了一项名为 greet 的操作。name 是字符串参数，默认值为 World；GString 同时描述类型约束与生成的 API 契约。hasheq 创建一个哈希表，返回 message 字段。module+ main 将启动窗口的动作与模块导入分开，因此检查 API 时不必打开窗口。

## 第二步：编写页面

将 public/index.html 替换为下面完整文件：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>问候应用</title>
  <style>
    body { font-family: system-ui, sans-serif; margin: 24px; }
    main { max-width: 480px; margin: auto; }
    input, button { font: inherit; padding: 8px; }
    output { display: block; margin-top: 16px; }
  </style>
</head>
<body>
  <main>
    <h1>问候应用</h1>
    <label for="name">姓名</label>
    <input id="name" value="Ada">
    <button id="greet">打招呼</button>
    <output id="reply" aria-live="polite"></output>
  </main>
  <script src="/glaze/api.js"></script>
  <script>
    const nameInput = document.getElementById("name");
    const button = document.getElementById("greet");
    const reply = document.getElementById("reply");
    button.addEventListener("click", async () => {
      button.disabled = true;
      try {
        const result = await glaze.api.greet({
          name: nameInput.value
        });
        reply.textContent = result.message;
      } catch (error) {
        reply.textContent = "调用失败：" + error.message;
      } finally {
        button.disabled = false;
      }
    });
  </script>
</body>
</html>
```

HTML 的 id 给元素一个可定位的名字。addEventListener 注册点击回调，await 等待异步 API 返回，textContent 将结果作为文本显示而非 HTML。try/catch/finally 分别处理正常执行、错误以及按钮状态恢复。即使暂时不熟悉 JavaScript，也可以先沿着这条数据路径理解代码。

## 第三步：运行和检查

```sh
raco glaze schema check --json
raco glaze schema write
raco glaze schema check --json
raco glaze dev
```

首次新增 greet 后，检查应能识别契约变化；确认这是有意增加的 API，再更新基线。不要为了通过检查而覆盖不兼容变化。打开窗口后输入 Ada，点击按钮，预期显示“你好，Ada！”。关闭窗口再运行：

```sh
raco glaze verify
raco glaze build --name myapp
```

verify 检查原生窗口等基础运行条件，不等于已经验证本章按钮业务功能。build 生成分发产物；真正发布还需要目标平台测试及适用的签名流程。

Glaze 的 0.x 文档区分默认 HTTP 适配器与显式 native 传输，两者都在原生 WebView 内运行。不要把本地 API 调用理解为必须访问互联网，也不要假设打包后自动具备跨平台发布资格。
