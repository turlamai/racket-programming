# 从控件到应用——理解现代 GUI 的三条路线

> 同一份任务业务逻辑，可以用 Racket 自带的控件、网页界面或平台原生界面来实现。不同的是界面的实现方式，不变的是数据、状态和事件。

上一章我们让一个窗口里的按钮改变了计数值。现在我们想做一个任务列表：每一项都有标题、备注与完成状态。选中的条目属于界面状态，暂不作为任务的数据字段。应该怎样组织代码？

## 先想清楚数据，再考虑界面

一个任务首先是一份数据，而不是屏幕上的一个矩形。

```racket
#lang racket
(struct task (title note done?) #:transparent)

(define milk (task "买牛奶" "周末之前" #f))

(define (finish t)
  (struct-copy task t [done? #t]))

(module+ test
  (require rackunit)
  (check-true (task-done? (finish milk)))
  (check-false (task-done? milk)))
```

把代码保存为 task.rkt，执行 `raco test task.rkt`。即使没有打开任何窗口，我们也可以验证完成任务的逻辑。这里 finish 返回一个新的任务，原任务没有改变。

界面的职责是展示任务，以及在用户操作时调用相应逻辑。

## 一次点击发生了什么

```text
用户点击按钮
     ↓
界面收到事件
     ↓
调用业务逻辑
     ↓
得到新的状态
     ↓
更新界面
```

例如，点击完成按钮后，程序调用 finish，随后按照返回的任务更新文字和勾选状态。这个过程可以写成回调，也可以使用声明式界面框架管理状态与视图之间的关系。

## 路线一：Racket 自带的控件

`racket/gui` 提供窗口、按钮、文本框、列表和布局容器。它适合快速构建工具，也是认识事件驱动编程的好起点。

```racket
#lang racket/gui

(define f (new frame% [label "任务"] [width 300]))
(define p (new vertical-panel% [parent f]))
(struct task (title note done?) #:transparent)
(define current-task (task "买牛奶" "周末之前" #f))
(define (finish t) (struct-copy task t [done? #t]))
(define status (new message% [parent p] [label "未完成"] [auto-resize #t]))
(new button%
     [parent p]
     [label "完成"]
     [callback (lambda (button event)
                 (set! current-task (finish current-task))
                 (send status set-label
                       (if (task-done? current-task) "已完成" "未完成")))])
(send f show #t)
```

这里的 callback 是一个函数，框架会在按钮被点击时调用它。panel 负责布局，message% 负责展示文字。复杂的组合交互可以通过自定义控件、事件处理和 canvas% 实现，但自绘也意味着程序需要承担更多绘制、命中测试及无障碍支持的工作。

## 路线二：Glaze，共享 Web 界面

如果希望用 HTML、CSS 和 JavaScript 表达界面，同时将应用逻辑保留在 Racket 中，可以采用 [Glaze](https://github.com/turlamai/glaze)。

Glaze 把 Web 界面放在桌面操作系统的 WebView 中，而不是要求用户打开浏览器。界面通过明确的 API 调用 Racket 后端。Windows、macOS 和 Linux 可以共享大部分界面代码，但仍需各自的 WebView 运行环境。

## 路线三：Rivet，平台原生界面

[Rivet](https://github.com/turlamai/rivet) 采用另一种分工：Racket 负责共享业务逻辑，Windows 使用 WinUI 3，macOS 使用 SwiftUI，Linux 使用 GTK4。各平台界面通过类型化的接口调用同一个 Racket 后端。

这种方式可以直接使用平台的界面能力，代价是需要维护不同平台的界面代码，并安装相应的开发工具链。

## 如何选择

| 目标 | 适合首先尝试的方案 |
| --- | --- |
| 学习事件、窗口和基本控件 | racket/gui |
| 希望共享 HTML/CSS/JS 界面 | Glaze |
| 希望直接使用各平台原生 UI 框架 | Rivet |

不存在适用于所有项目的唯一答案。两个外部库也不是 Racket 标准库，安装、版本和平台支持需要单独确认。它们的官方文档是具体 API 与环境要求的参考依据。

## 动手练习

给前面的 task 增加一个撤销完成状态的函数，再写测试验证它。

参考答案（追加到 task.rkt）：

```racket
(define (reopen t)
  (struct-copy task t [done? #f]))
(module+ test
  (check-false (task-done? (reopen (finish milk))))
  (check-equal? (reopen (finish milk)) milk))
```

随后在 GUI 示例中增加 reopen 和撤销按钮，参照完成按钮的写法更新 current-task，再依据 task-done? 更新文字。想一想：如果明天换了一种界面技术，哪些代码能够原封不动地留下来？
