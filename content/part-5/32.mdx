# Rivet——从 Racket 业务逻辑到平台原生窗口

> Rivet 将共享的 Racket 业务逻辑嵌入平台原生应用，使用生成的类型化客户端连接界面与后端。本章先运行脚手架，再扩展一个后端操作。

Glaze 用共享的 HTML/CSS/JavaScript 界面在 WebView 中渲染。Rivet 采用另一条路线：Windows 用 WinUI 3，macOS 用 SwiftUI，Linux 用 GTK4。三者共享 Racket 业务逻辑和通信契约，但界面源码分别维护。

## 为什么要有边界

假设应用需要一个计数器。当前数值和加一规则不依赖操作系统，适合放在 Racket 后端；按钮、窗口布局和平台交互则由原生界面负责。

## 安装与运行

需要 Racket 9.0 或更新版本的 CS 实现。运行：

```sh
raco pkg install --auto rivet
raco rivet help
raco rivet new hello-rivet
cd hello-rivet
raco rivet doctor
```

Windows 需要 Visual Studio C++/Windows SDK 等工具；macOS 需要 Apple 开发工具链；Linux 需要 C++20、CMake、GTK4 开发文件及可嵌入的 Racket CS 运行时。具体版本和修复步骤以 [Rivet 项目官方文档](https://github.com/turlamai/rivet) 的 Getting Started 为准。

doctor 确认当前机器的工具链后运行：

```sh
raco rivet dev
```

脚手架应打开当前平台的原生计数器窗口。点击 Increment in Racket，观察数值更新。开发命令负责构建当前平台宿主、生成客户端并连接 Racket 后端，不代表其他平台的构建已经通过。

## 认识项目结构

| 路径 | 职责 |
|---|---|
| app/backend.rkt | 共享的 Racket 后端 |
| rivet.rktd | 项目标识与部署配置 |
| rivet-schema.json | 接口兼容性基线 |
| tests/smoke.rkt | 初始测试 |
| windows/ | WinUI 3 界面 |
| macos-host/ | SwiftUI 界面 |
| linux/ | GTK4 界面 |

初始后端声明了事件 notification 和状态 counter，例如：

```racket
(define-event notification : String)
(define-state counter : Int64 0)
```

事件适合通知已经发生的事情，状态适合表达当前值。Int64 是接口约定中的有符号 64 位整数类型，不是对 Racket 所有整数的限制。

## 增加一个远程过程

打开 app/backend.rkt，保留已有声明、启动函数及模块导出，在现有 RPC 声明附近新增：

```racket
(define-rpc (exclaim [text : String] : String)
  (format "~a!" text))
```

RPC（Remote Procedure Call）在这里表示跨界面与后端边界调用一个过程；不意味着必须经过互联网。这个操作接收一个字符串，并返回末尾带感叹号的字符串。

重新运行 raco rivet dev 后，工具会生成新的类型化客户端。查看生成的 API，再按照当前平台已有的异步调用方式接入 exclaim。仅增加后端声明不会自动生成一个界面按钮。

## 在哪里修改界面

Windows 从 windows/MainWindow.xaml 和 windows/MainWindow.xaml.cpp 开始；macOS 从 macos-host/Sources/RivetHost/ContentView.swift 开始；Linux 从 linux/src/main.cpp 开始。它们分别使用原生界面技术。建议先只修改当前平台，理解共享后端如何与界面协作，再移植另一平台。

避免在 UI 线程同步等待耗时操作。原生窗口的事件处理与界面更新需要遵守各平台线程规则。

## 检查与打包

新增 RPC 后先确认兼容性检查的结果，再有意更新基线：

```sh
raco rivet schema check rivet-schema.json --json
raco rivet schema --output rivet-schema.json
raco rivet schema check rivet-schema.json --json
raco rivet build
raco rivet package
raco rivet verify
```

生产发布还需要平台签名、验收测试及实际目标设备验证。移动端能力与桌面工具链不应混为一谈；本章仅覆盖 Windows、macOS、Linux 桌面宿主。

## 动手练习

先完成脚手架计数器的本机运行，再新增 exclaim，观察生成客户端的变化。最后尝试为当前平台的界面增加一个调用它的按钮。预期输入 Hello 后得到 Hello!。
