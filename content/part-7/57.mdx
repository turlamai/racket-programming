# xexpr——HTML 是数据，不是字符串

> HTML 可以用文本表示，也可以先构建结构化数据，再序列化成文本。本章介绍 Racket 的 xexpr 约定，以及 Loom 的页面构建入口。

浏览器接收 HTML 文本，再解析出文档结构。服务端既可以生成字符串，也可以先构造树形数据。Racket 的 xexpr 采用后一种思路。

## HTML 的本质：不是文本，而是结构

从浏览器的角度看，HTML 是文本；但从程序的角度看，它更接近一棵树：

```html
<div>
 <h1>Hello</h1>
 <p>Welcome</p>
</div>
```

这里 div 表示容器，h1 表示一级标题，p 表示段落。开始标签和结束标签围住内容，元素也可以嵌套。浏览器按 HTML 规则解析文本，形成文档树（DOM）。下面只画出这个例子的主要元素：

```text
div
 ├─ h1 → "Hello"
 └─ p → "Welcome"
```

如果你熟悉 Lisp 或 Racket，这种结构会立刻让你想到一件事：

> **这正是列表和嵌套列表最擅长表达的东西。**

## 二、什么是 xexpr？

**xexpr（XML Expression）** 是 Racket 用来表示 HTML / XML 的一种数据约定。

一句话定义：

> **xexpr = 按约定使用 Racket 值表示 XML 风格的结构；在 Web 程序中也常用于构建 HTML**

### 最基本的例子

HTML：

```html
<h1>Hello</h1>
```

xexpr：

```racket
'(h1 "Hello")
```

- `h1` 是标签名
- `"Hello"` 是子节点

### 嵌套结构

HTML：

```html
<div>
 <h1>Hello</h1>
 <p>Welcome</p>
</div>
```

xexpr：

```racket
'(div
 (h1 "Hello")
 (p "Welcome"))
```

规律非常清晰：

> **元素形式以标签符号开头，可选属性列表之后才是子节点。**

## 三、xexpr 不是字符串，而是普通数据

这一点非常重要。xexpr 并不是“模板语法”，常见元素节点用 Racket 列表表示，文本节点则可以是字符串。任意列表并不一定是合法 xexpr。

你可以：

- 把它赋值给变量
- 作为函数返回值
- 用 `map`、`if`、`cond` 操作它

## 四、在 Web Server 中使用 xexpr

xexpr 本身只是数据；在 servlet 里，需要用 `response/xexpr` 把它转换成 HTTP response。

一个最小示例：

```racket
#lang racket

(require web-server/servlet
 web-server/servlet-env
 web-server/http)

(define (start request)
 (response/xexpr
  '(html
    (head
     (title "xexpr Example"))
    (body
     (h1 "Hello")
     (p "This page is written in xexpr.")))))

(serve/servlet start
 #:port 8000
 #:listen-ip "127.0.0.1"
 #:servlet-path "/"
 #:launch-browser? #t)
```

保存为 page.rkt，在终端执行 `racket page.rkt`，并访问 http://127.0.0.1:8000/ 。预期看到标题 Hello 和下方段落。按 Ctrl+C 停止本地服务。

这里的关键点在于：

> **你先用 xexpr 表达结构，再用 `response/xexpr` 把结构序列化成 HTML response**

## 五、HTML 属性如何表示？

HTML：

```html
<p class="intro">Hello</p>
```

对应的 xexpr：

```racket
'(p ((class "intro")) "Hello")
```

属性规则统一而明确：

```text
(tag
 ((attr-name attr-value) ...)
 child ...)
```

例如：

```racket
'(a ((href "https://racket-lang.org"))
 "Racket")
```

不需要手动拼接标签，但仍需遵守 xexpr 结构约定。

## 六、xexpr 的真正优势：可编程性

xexpr 的价值并不在于“能写 HTML”，而在于：

> **HTML 终于可以像程序一样被组合、抽象和复用。**

### 1 条件生成页面

```racket
(define (message logged-in?)
 `(div
 (h1 "Welcome")
 ,@(if logged-in?
 '((p "You are logged in"))
 '((p "Please log in")))))
```

这里使用了 Racket 的反引号语法：

- `` ` ``：构造结构
- `,`：把计算结果插入为一个元素。
- `,@`：把计算所得列表的各个元素逐个插入外层列表。

```racket
(define children '((p "A") (p "B")))
`(div ,children)  ;; '(div ((p "A") (p "B")))
`(div ,@children) ;; '(div (p "A") (p "B"))
```

这里需要第二种写法，才能使两个 p 成为 div 的直接子节点。

HTML 成了表达式的一部分。

### 2 列表驱动的页面生成

```racket
(define (item-list items)
 `(ul
 ,@(map (λ (item)
 `(li ,item))
 items)))
```

这段代码表达的不是“拼页面”，而是：

> **对一个列表进行映射，得到另一棵结构**

## 七、页面就是函数

一旦你接受 xexpr 是数据，一个自然的结论是：

```racket
(define (page title body)
 `(html
 (head (title ,title))
 (body ,@body)))
```

使用方式：

```racket
(page "Home"
 '((h1 "Home")
 (p "Welcome to this site.")))
```

这里没有模板，没有宏法术，只有函数。

## 八、xexpr 的心智模型

可以用三句话概括 xexpr：

1. HTML 是树
2. 树可以用列表表示
3. 列表是 Lisp 的母语

因此：

> **在 Racket 里写 HTML，不是绕远路，而是走直线。**

## 九、对新手来说，为什么这是好事？

对于没有前端背景的人，xexpr 有明显优势：

- 没有额外的模板语言
- 没有隐藏的上下文变量
- 减少手动拼接和转义错误

你看到的，就是你构造的数据。

## 在 Loom 中构造页面

回到第 55 章已经介绍的 Loom。本例使用 loom/html 提供的组件与元素构造器：

```racket
#lang racket
(require loom loom/html)

(define-component (welcome name)
  (element 'h1 "Hello, " name))

(define app
  (make-app
   (list
    (route #"GET" "/"
           (lambda (_request)
             (html-response
              (page-layout #:title "Welcome"
                           (welcome "Racket"))))))))

(serve app)
```

需要先按第 55 章安装 Loom 的对应开发版本。保存为 welcome.rkt，执行 `racket welcome.rkt`，访问 http://127.0.0.1:8080/ ，预期显示 Hello, Racket。该示例仍需实际版本运行验证，不代表生产环境配置。

## 结构化 HTML 不等于完整安全策略

使用字符串文本节点可以避免将普通用户文本直接解释为标签，但 URL、脚本、样式和事件属性仍需要各自的安全策略。不要将用户输入转换成任意标签名或属性名。Loom 的 loom/html 提供受约束的 element 与 page-layout 构造器，限制某些危险标签和属性；它不是通用 HTML sanitizer。原始 html-response 应用于可信结构。

## 结语

在 Racket 中，HTML 不再是“页面文件”，而是你程序中的一种 **普通结构值**。

一旦你理解了 xexpr：

- 页面可以被函数化
- 结构可以被组合
- Web 编程不再是特殊领域

它只是你熟悉的 Racket 世界，在网络上的一次自然延伸。

Web 讲到这里，你已经能用 Racket 写服务、存数据、生成页面、部署上线。下一篇换个方向——当 Racket 自己的能力不够用时，怎么通过 FFI 调用 C 的库，把两门语言的能力拼在一起。
