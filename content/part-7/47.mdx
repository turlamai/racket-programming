# raco——Racket 工程体系的控制中心

> `raco` 不只是装包的命令，它是 Racket 工程体系的控制中心——包管理、编译、测试、打包发布，全在这一个工具里。

你其实早就用过 `raco` 了：装第一个第三方包，敲的就是 `raco pkg install`。大多数人对它的认识也停在这一步——一个装包的命令，类似 Python 的 `pip`。

这就把 `raco` 看小了。装包只是它的一小块：跑测试、编译、生成可执行文件、重建文档索引、排查安装后的诡异问题，全都在这一个入口后面。别的语言里这些活儿分属一堆工具，Racket 把它们收成了一个。

## 别的语言是一堆工具，Racket 是一个入口

回想你熟悉的技术栈：

- Python：pip 管包，setuptools 管打包，pyinstaller 管可执行文件，各管一段
- JavaScript：npm 管包，webpack、vite 管构建，又是一套
- Rust：cargo 已经统一了大半，外围仍要自己配

`raco` 的思路是把工程侧全部收进一个入口，所有日常工程操作都是它的一个子命令。更特别的是，这些子命令并不神圣——它们本质是普通的 Racket 程序，跟着包系统走。你装的某个包，就可以给 `raco` 增添新命令，和官方命令平起平坐。工具生态跟着语言一起长，这是"语言即工具"的设计哲学。

## raco pkg：包的生命周期

包管理是最常用的一支：

```bash
# 安装远程包

raco pkg install --auto rackunit-lib

# 本地开发模式（推荐）

raco pkg install --link .
```

`--link` 值得单独说一句：它不把包复制进安装目录，而是"链接"到你的本地源码。链接安装使包指向源码目录；已运行进程中的模块通常仍需重新加载或重启，元数据和文档变更也可能需要 setup——这是自己开发包时的标准工作方式。

还有一个认知要建立：**Racket 的包不只是库**。一个包可以同时装着库代码、可执行程序、文档、甚至 `raco` 的工具扩展。你发布一个包，可以同时给生态提供库和命令。

## raco exe：从脚本到可执行文件

```bash
# 生成可执行文件

raco exe main.rkt
```

这一步会把模块及其运行时支持打进一个平台可执行文件，但它还不等于“拷到任意一台没装 Racket 的机器就一定能跑”。可执行文件仍可能依赖共享库和运行时文件；真正要做可搬运的发行目录，还要再用 `raco distribute` 把这些依赖收齐。第 49 章会把这条分发链路完整走一遍。

## raco setup：出怪事先找它

`raco setup` 是最容易被忽视、又最常救你命的一个：编译新装的包、重建文档索引、检查依赖一致性、生成优化缓存，全是它在背后做。先检查实际 Racket 版本、包安装范围、依赖和错误日志。确有编译或文档问题时，可针对包运行 raco setup --pkgs 包名，不必每次重建所有包。

## 包、应用、工具：一个项目的三张面孔

| 类型 | 使用方式 | 分发方式 |
|------|----------|----------|
| 库 | `(require ...)` | 通过 `raco pkg` 安装 |
| 应用 | 直接运行 | `raco exe` 生成可执行文件，`raco distribute` 收齐分发依赖 |
| 工具 | `raco xxx` 命令 | 作为包的一部分 |

这三样不是三种项目，而是同一个包的三张面孔：一个项目完全可以既被 `require`，又能直接运行，还顺手给 `raco` 贡献一个子命令。理解了这一点，你就明白为什么 Racket 敢把工程侧收进一个工具——它管的从来不只是"库"，而是你项目的一生。

## 把 raco 用起来

先在一个空目录创建 main.rkt：

```racket
#lang racket/base
(define (double n) (* 2 n))
(module+ main (displayln (double 21)))
(module+ test
  (require rackunit)
  (check-equal? (double 21) 42))
```

这个单文件程序不需要先安装为包。确认本机具有 rackunit-lib，再执行以下工作流：

```bash
# 测试阶段
raco test main.rkt

# 编译检查
raco make main.rkt

# 发布阶段（按目标平台执行）
raco exe main.rkt
raco distribute dist main
```

Windows 使用 `raco exe -o main.exe main.rkt` 和 `raco distribute dist main.exe`。在分发目录中确认实际入口路径并运行，预期打印 42。不要只复制入口文件或把当前平台生成的二进制文件当成跨平台产物。下一章再建立可链接安装的包。

之后每次遇到新的工程需求——文档生成、部署、格式检查——先别急着找第三方工具，先问一句 `raco` 有没有现成的子命令。这个习惯会让你在 Racket 生态里事半功倍。
