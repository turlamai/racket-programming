# Racket Programming DESIGN.md — 视觉与交互契约（单一真源）

原型（`design/prototype/`）与实现（`app/` `components/`）都遵循本文件；改视觉先改这里，再同步实现。
Tokens 提取自 `app/globals.css` 与 `tailwind.config.js` 现行值，保证原型 → Next.js/MDX 实现零翻译成本。
亮色列即站点现行值；**暗色列与标注「推导」的条目为本契约推导定稿**（站点现无暗色主题），实现时照搬、不在实现处重新发明。

## Brief（2026-11-11）

- **目标**：非从零重设计。在既有暖纸色体系上做 HIG 级梳理，把「中文长文排版」与「代码呈现」这两个本书的核心产品资产在契约里显式固定；界面达到可直接用作宣传素材的质量。
- **原型范围**（5 屏 × 亮/暗）：① 首页（英雄屏，全书结构入口）② 卷目录（章节导航）③ 章节阅读（长文排版 + 代码块 + 勘误反馈 + 章节间导航）④ 代码示例呈现（高亮对照 / 复制态 / REPL 输出 / 错误态）⑤ 移动端阅读（顶栏 + 抽屉目录）。
- **Exit 条件**：5 屏关键状态齐（含复制成功态、抽屉展开态、当前章选中态）+ 交互逻辑定稿 + HIG 清单全过 + 用户评审通过。
- **不在范围**：暗色下的代码高亮重配色（双主题共用一套深底高亮，见不变式 3）、全文搜索（站点现无此功能）、评论/社区功能、任何付费/授权 UI（决策 2026-10-auth-1：保持免费内容）、桌面客户端形态。

## 设计原则（HIG 内核）

- **阅读至上**：正文与代码是唯一主角。侧栏、眉题、反馈盒全部退成小字号低对比 chrome，正文区不出现与内容争夺注意力的装饰。
- **中文长文是产品资产**：版心 72ch、行高 1.8、字号阶恒定；标题不孤行、列表不散架。长文排版细节就是这本书的门面，任何界面改造不得为省空间牺牲它。
- **代码即展品**：代码块在任何主题下保持深色底高亮（沿用现行实现的选择），像展柜里的展品；注释斜体灰色，输出写在 `;;` 之后；复制一键可得且有成功反馈。
- **章节导航直接明了**：上一章/下一章固定在正文末尾同一位置；侧栏常驻标明当前章；读者任何时刻都知道自己在全书 60 章 + 附录中的位置。
- **反馈常驻但不打扰**：勘误入口每页文末常驻（这本书靠读者勘误持续修订），选中正文即浮出「反馈这段」；反馈流永不阻塞、不遮挡阅读。
- **键盘与焦点可达**：全部链接与按钮可 Tab 聚焦，焦点环 2px accent；纯键盘也能完成「读 → 翻页 → 反馈」。

## 组件词汇

`BrowserShell`（原型壳：地址栏 + 主题切换 ◐）· `TopBar`（移动端顶栏 ☰ + 书名）· `Sidebar`（卷树：写在前面 / 问题反馈 + 七卷 + 附录，可折叠，当前章 accent 标亮）· `PartHeader`（眉题 + 卷题 + 卷描述）· `PartRow`（首页卷行：眉题 + 卷题 + 简介 + 章数徽标，章数徽标为推导）· `ChapterRow`（双位等宽编号 + 章题 + 一句简介）· `Prose`（长文排版：标题阶 / 列表 / 引用 / 表格 / 行内代码）· `CodeBlock`（深底高亮 + 复制按钮 + `;;` 输出注释 / REPL `>` 提示）· `InlineCode`（raised 底 + 焦橙小片）· `ChapterNav`（上一章/下一章，正文末尾固定位置）· `FeedbackBox`（有帮助 / 反馈问题 + GitHub 编辑入口）· `SelectionPill`（选中正文浮出「反馈这段」）· `Footer`（许可 + 阅读帮助链接，仅首页）。

## 不变式

1. `accent` 只给交互与状态：链接、当前章节、焦点环、进行态；标题与正文不用 accent，正文除引用条线（`--accent-soft` 边）外禁止大面积橙。
2. 版心恒定 72ch：任何屏幕正文行长不得拉伸；侧栏只承担目录与入口，不塞内容。
3. 代码块双主题同为深底，高亮只用上表 8 色；这是有意的「展品」处理，不为暗色单独调第二套高亮。
4. 亮暗成对：每个界面、每种状态（含复制成功/选中/抽屉）都有亮暗两态，不存在单态界面。
5. 章节间导航（上一章/下一章）永远在正文末尾、反馈盒之后、位置不变；跨卷翻页时标明目标章所属卷。
6. 反馈与勘误入口每页常驻，但位于阅读流之外（文末/选中浮出），永不遮挡正文。
